# Hijab Haven — Shop App

This folder contains the new Hijab Haven website: the customer shop
(hijab-haven.netlify.app) and the admin area (`/admin`) where you manage
products, orders, customers, WhatsApp broadcasts, and admin accounts.

It replaces the old single-file `index.html` site. Orders are now saved in a
database (Supabase) as well as arriving on WhatsApp. There is no monthly cost:
the site runs entirely on the Netlify free plan and the Supabase free plan.

## What is in this folder

| Folder / file | What it is |
|---|---|
| `src/` | The app's source code (pages, components, logic) |
| `public/images/` | The two brand images: `logo.jpg` and `upi-qr.jpg` (UPI payment QR) |

are" at the bottom).

## Running the site on your computer (local development)

You only need this if you (or your developer) want to change the site.

**Prerequisite:** Node.js version 22 — download from https://nodejs.org
(check with `node --version`).

1. Open a terminal in this folder (`app`).
2. Install dependencies (first time only):
   ```
   npm install
   ```
3. Make sure the file `.env.local` exists in this folder with exactly these
   two lines (these are the real values — the second one is a *publishable*
   key, safe to use here):
   ```
   VITE_SUPABASE_URL=https://tacjzpobeoxyrdrvazni.supabase.co
   VITE_SUPABASE_ANON_KEY=sb_publishable_P3yvDhbFdSmDnxbgTSROrw_1ef6-TA4
   ```
4. Start the site:
   ```
   npm run dev
   ```
   It opens at http://localhost:5173

## FIRST-TIME GO-LIVE CHECKLIST

Do these once, in this exact order. (The same checklist, on its own, is at
`..\GO_LIVE.md` — that file is your single entry point for launch day.)

1. **Set up the database.** Follow every numbered step in
   `..\docs\SUPABASE_SETUP_CHECKLIST.md`. That covers: running the migration
   SQL, the verification queries, the dashboard settings (email OTP expiry,
   site URLs), and creating YOUR super-admin login account.

2. **Delete the QA test row.** Testing left one fake customer in your
   database. In the Supabase dashboard → SQL Editor, run:
   ```sql
   DELETE FROM customers WHERE phone='0000000000';
   ```
   (That removes the row named "QA Smoke Test" — nothing else.)

3. **Create a STAGING site on Netlify** (a private practice copy — your live
   site is untouched):
   1. Push the code to GitHub first if you have not (see `..\GO_LIVE.md`,
      "Publish to GitHub").
   2. Netlify dashboard → **Add new site → Import an existing project →
      GitHub** → pick the `hijab.haven.shop` repository → pick the `rebuild`
      branch.
   3. Build settings fill themselves in automatically (they are read from the
      `netlify.toml` file at the top of the repository: base `app`, command
      `npm run build`, publish `dist`, Node 22). Do not change them.
   4. Before (or right after) the first deploy: **Site settings → Environment
      variables → Add** the same two variables from `.env.local` above:
      `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`. If the first deploy
      ran before you added them, click **Deploys → Trigger deploy** once more.
   5. You get a random URL like `https://something.netlify.app` — that is
      staging.

4. **Verify on staging** (these were deferred by QA because they need real
   accounts — see `..\docs\QA_REPORT.md` section 8):
   - **Admin login round-trip:** sign in at `/admin/login` with your
     super-admin email+password → you land on the dashboard. Also confirm a
     NON-admin account is rejected with "Not an admin account".
   - **Customer OTP round-trip:** on `/auth`, enter a real email → receive the
     6-digit code → sign in → `/account` shows your profile.
   - **One real guest order, end to end:** add a product to cart → checkout →
     all 3 steps → the WhatsApp message opens correctly (with the HH-000NN
     order code) AND the order appears in `/admin/orders`.
   - **Looks identical:** compare staging vs the current live site
     side-by-side at phone width (390px) and desktop width (1440px) — colors,
     fonts, spacing, and wording must match.

5. **Production cutover** (point your real address at the new app):
   1. Netlify dashboard → your existing **hijab-haven** production site →
      **Site settings**.
   2. Connect it to the same GitHub repository and branch (`rebuild`), with
      the same auto-read build settings, and add the same two environment
      variables. Deploy.
   3. The old `index.html` stays in the repository but is no longer served.
   - **Rollback (if anything looks wrong):** Netlify → production site →
     **Deploys** → click the last good deploy from before the cutover →
     **Publish deploy**. The old site is back within a minute. Fix the
     problem on staging, then cut over again.

6. **Post-cutover smoke test** on https://hijab-haven.netlify.app:
   - Open in a private/incognito window → the entry gate appears → enter a
     name+phone → it closes and the row appears in `/admin/customers`.
   - Browse `/shop`, open a product, add to cart.
   - Place one real order → WhatsApp message arrives → order visible in
     `/admin/orders` → move it pending → confirmed.
   - Sign in at `/admin/login` on the production URL.
   - Deep-link test: open `https://hijab-haven.netlify.app/shop` directly in
     a new tab — it must load (not 404).

## How to add another admin

1. Supabase dashboard → **Authentication → Users → Add user → Create new
   user**: enter their email and a strong password, tick "Auto Confirm User",
   then copy the new user's **UID** (the long id).
2. In the shop app, sign in as YOUR super-admin account → go to
   `/admin/admins` → add the new admin using that UID and email, choosing the
   role (`admin` = manage shop; `super_admin` = can also manage admins).

Only a super_admin can add or remove admins. Step-by-step SQL alternative:
`..\docs\SUPABASE_SETUP_CHECKLIST.md`, Parts 4–5.

## Free-tier notes (normal behavior, not bugs)

- **Supabase pauses free projects after about 7 days with zero activity.**
  Normal shop traffic prevents this. After a long quiet period (e.g. a
  holiday), the site may show the cached catalogue and new orders may fall
  back to WhatsApp-only; fix is one click: Supabase dashboard → your project
  → **Restore**. It takes a couple of minutes.
- **Netlify free plan:** 100 GB bandwidth and 300 build minutes per month —
  far more than this shop uses. Nothing to do.

## Security rules (please read once)

- The key in `.env.local` (`sb_publishable_...`) is **meant to be public** —
  every visitor's browser receives it. It can only do what the database's
  Row Level Security (RLS) rules allow. RLS is the real lock on the door.
- **NEVER put the Supabase "service role" key** in this app, in the
  repository, or in Netlify settings. That key bypasses ALL security; anyone
  who gets it can read and delete everything. It must never leave the
  Supabase dashboard.
- Admin pages are protected by your admin login. The old PIN (1226) no longer
  exists anywhere.
